## 5. Уроки и инварианты (HARNESS-002)

### STD-LM-001 | Паритет токена ingest-цепочки «config.php ↔ FunnelHub»; .bak в web root = утечка секрета (2026-11-07)
* **Сигнал/Маркер (Cue):** most.aisukam.ru форма, `/api/application/`, `funnelhub_application_token`, `401 Invalid landing application token`, «заявки не доходят», «0 лидов Моста», config.php, `FTP_MOST_USER/PASS`.
* **Проблема & Причина:** в FTP `config.php` (корень сайта на Reg.ru) токен 43 симв. против серверного 64 (`MOST_TSENNOSTEY_INGEST_TOKEN` FunnelHub) → каждая реальная заявка отбивалась 401 МОЛЧА (PHP не логирует, у FunnelHub нет access-логов — STD-FUNNEL-008) → 0 лидов за всё время. При этом оба звена ПО ОТДЕЛЬНОСТИ живы (PHP 422 на кривые данные, FunnelHub 401 на чужой токен) — деградация не видна ни с одной стороны, только сравнением значений.
* **Стандарт и контрмера:**
  1. Паритет токена проверять сравнением значений «FTP config.php vs сервер .env» (без печати значений) при любом подозрении на потерю заявок.
  2. Обновление токена: скачать текущий → бэкап ТОЛЬКО локально (tmp/) → залить новый → повторно скачать и сравнить. Бэкап не хранить на хостинге.
  3. Файлы с секретами (config.php.bak и любые не-.php копии) НИКОГДА не оставлять в web root хостинга — Apache исполняет только .php, остальное отдаётся как plain text с секретом внутри.
  4. Локальное зеркало живого конфига = `php-hosting/config.php` (gitignored) — править при каждом изменении на FTP.
* **Доказательство (Evidence):**
  - ДО: `TOKEN COMPARISON (vault vs php): MISMATCH` (43 vs 64 симв.); в БД FunnelHub 0 лидов `most-tsennostey`.
  - ПОСЛЕ: `uploaded token == vault token: True` (повторное скачивание), зонд с правильным Bearer → 422 (валидация, не 401); живой тест пользователя 2026-11-07 — заявка дошла до вкладки «Мост ценностей».
  - Web root: проба `php-probe-20261107.txt` → `200 MARKER-PLAINTEXT-PROBE` (отдаётся как есть), после удаления → 404.
